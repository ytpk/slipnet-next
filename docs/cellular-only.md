# Мобильная сеть для туннелей: статус реализации

Это **частичная реализация**, а не поддержка всех ядер SlipNet.
Базовая ревизия: `2ed00fd0072ad0b558e30ec6b5e8b30948f98894` (SlipNet 2.5.6).
ARM64 APK собирается в GitHub Actions; работа на реальном Android не проверена.
Пакет тестовой сборки — `app.slipnet.next`, подпись — debug.

## Что реализовано

В Settings → Connection добавлен переключатель **Mobile data for tunnels (4G/5G)**.
По умолчанию он выключен. Изменение применяется после переподключения.

Для Slipstream, Slipstream + SSH, SSH, DoH, SOCKS5 и VLESS:

- удерживается отдельный запрос `TRANSPORT_CELLULAR`, без отключения Wi-Fi;
- исходящие Kotlin TCP/UDP-сокеты привязываются к выбранной `Network`;
- bootstrap DNS, UDP DNS, DoH и системное разрешение имён в изменённых путях используют мобильную сеть;
- Rust Slipstream получает числовые адреса резолверов; его JNI-сокеты привязываются после `protect()`;
- VPN объявляет только мобильную сеть в underlying networks;
- соединения между слоями остаются на loopback, слушающие и принятые LAN-сокеты не привязываются к мобильной сети;
- изменения Wi-Fi не запускают штатное переключение туннеля на Wi-Fi;
- при потере мобильной сети сеанс останавливается; для продолжения нужно переподключение;
- запрос сети освобождается при завершении сеанса, ошибке, тайм-ауте и отмене ожидания.

Используется привязка отдельных сокетов, без `bindProcessToNetwork()`.
Режим также применяется к цепочкам, состоящим из поддержанных типов.
Настройки адреса/порта LAN-прокси остаются существующими настройками SlipNet.

## Что НЕ реализовано

В этом режиме намеренно запрещены DNSTT, NoizDNS, VayDNS, Soar, Tor/Snowflake,
NaiveProxy и их составные варианты. Цепочка с таким слоем также не запускается.
Их Go-сокеты и отдельные исполняемые процессы требуют собственной интеграции
с Android Network. JVM-привязка не даёт гарантии для этих путей, поэтому
ошибочное обещание работы через мобильную сеть заменено явной ошибкой запуска.
Когда переключатель выключен, эти типы работают по исходной логике приложения.

Для завершения исходного требования «все туннели» нужно внедрить fail-closed
привязку **до connect/send** во все Go TCP/UDP/DoH/DoT пути, их DNS resolver,
а также в отдельные процессы Naive, Tor и lyrebird. Затем пересобрать соответствующие
AAR/бинарники и проверить их трафик на устройстве.

`TRANSPORT_CELLULAR` выбирает мобильную сеть активной SIM, а не конкретный радиостандарт.
Ограничить LTE вместо 5G/3G может пользователь в настройках телефона.
Выбора SIM в этом изменении нет.

Остановка VPN не является общесистемным kill switch: после отключения VPN
обычный трафик Android регулируется настройками телефона. Режим относится
к исходящим соединениям SlipNet. Обход VPN некоторыми приложениями и системным
Private DNS — отдельная настройка Android.

## Проверки

Пройдена полная сборка `:app:assembleFullDebug` для ARM64 с Android SDK 36.
В GitHub Actions прошли 11 JUnit-тестов с Mockito (`:app:testFullDebugUnitTest`):
выбор мобильной сети, отмена, тайм-аут, недоступная сеть, потеря во время запуска,
потеря после запуска, поздние callback, DNS без fallback, TCP bind до connect,
доступ к loopback-прокси, выключенный режим.
Это тесты логики с подменой Android API. Они не подтверждают маршрутизацию на устройстве.
`git diff --check` также пройден.

В CI также проверяется подпись APK через `apksigner verify` и его манифест через `aapt`.
Сборка и автоматические тесты не заменяют проверку маршрутизации на устройстве.

## Проверка на OnePlus 9RT

Нужны реальная версия Android/OxygenOS и проверка на телефоне:

1. Включить Wi-Fi и мобильную передачу данных. Проверить доступ к домашнему роутеру.
2. Включить новый режим и переподключить поддержанный профиль.
3. Сравнить IP трафика через туннель с IP мобильного подключения.
4. Проверить подключение к LAN-прокси с ПК по IP телефона, отключив изоляцию
   Wi-Fi-клиентов на роутере, если она включена.
5. Заблокировать интернет на Wi-Fi-роутере, сохранив LAN. Туннель должен продолжить работу.
6. На роутере проверить отсутствие исходящих соединений телефона к серверам туннеля
   и DNS, в том числе TCP/UDP 53, DoT и DoH. Проверить холодный старт с доменными адресами.
7. Выключить мобильные данные при доступном интернете по Wi-Fi: туннель должен
   остановиться и не переподключиться через Wi-Fi.
8. Повторить для VPN/proxy-only, поддержанных цепочек, IPv4/IPv6, смены IP мобильной
   сети, блокировки экрана и нескольких циклов подключения/отключения.
9. Проверить явную ошибку для неподдержанных типов и работу исходного режима
   при выключенном переключателе.

## Сборка форка

```bash
git clone https://github.com/ytpk/slipnet-next.git
cd slipnet-next
git submodule update --init --recursive app/src/main/rust/slipstream-rust dnstt noizdns vaydns vaydns-mobile
```

Для этой ревизии требуются SDK 36, NDK 29.0.14206865, Java 21 для Gradle
(target bytecode 17), Rust/OpenSSL и `app/libs/golibs-full.aar`.
Библиотека собирается через `gomobile-build/Makefile`. Полная воспроизводимая
последовательность для ARM64 находится в `.github/workflows/build.yml`.
Архитектуру можно ограничить свойством `-PtargetAbis=arm64-v8a`;
без свойства остаётся исходный набор из трёх архитектур.

```bash
./gradlew :app:testFullDebugUnitTest :app:assembleFullDebug -PtargetAbis=arm64-v8a
```

APK будет в `app/build/outputs/apk/full/debug/`.
Тестовые APK публикуются в [Releases](https://github.com/ytpk/slipnet-next/releases).
